# SPEC: тональность находок

Статус: **утверждена** владельцем.

## Зачем это читателю сводки

Читатель быстро понимает общий настрой материала по отношению к искусственному интеллекту — критикует ли материал ИИ, нейтрален или настроен оптимистично. Оценка видна рядом с находкой и в веб-ленте, и в сводке Telegram-бота.

## Что меняется и в каких файлах

- `worker/main.py`: модель возвращает `tone` от 1 до 5; worker проверяет значение и сохраняет его для новых находок. Старые находки не переанализируются и остаются без оценки.
- `db/schema.sql`: у `findings` появляется nullable-колонка `tone` с ограничением от 1 до 5. Новые значения `NULL` допустимы, если модель вернула некорректный ответ или запрос завершился ошибкой.
- `web/main.py`: цветной бейдж с числом от 1 до 5 рядом с находкой; для записи без оценки — серый прочерк.
- `bot/main.py`: цветной эмодзи в строке находки; если оценки нет — строка остаётся без эмодзи.
- `tests/test_schema.py`, `tests/test_tone.py`, `tests/test_web_badge.py` и `tests/test_bot_lines.py` проверяют соответствующие части.

Шкала относится к общему тону материала по отношению к ИИ: 1 — критика или страх, 3 — нейтрально, 5 — оптимистично. Значения 2 и 4 — промежуточные уровни. В ленте оценки отображаются числами с цветом от красного к синему; в боте — соответствующими эмодзи: 🔴 🟠 🟡 🟢 🔵.

Оценка рассчитывается только для новых материалов, обработанных после выкладки изменения. Старые находки остаются без оценки: в ленте у них серый прочерк, а в Telegram-сводке эмодзи не показывается. Если модель вернула некорректный ответ, значение остаётся `NULL`.

## Как проверим

- Запустить все тесты командой `pytest` из корня репозитория.
- Тест схемы подтверждает nullable-колонку `tone` и ограничение `1..5`.
- Тесты worker подтверждают разбор значений `1..5`, отказ для некорректных ответов и запись оценки для новой находки.
- Тесты ленты и бота проверяют отображение каждой оценки и поведение при отсутствии оценки.
- После выкладки выполнить в Postgres:

  ```sql
  SELECT prompt_version, tone, count(*) FROM findings GROUP BY prompt_version, tone ORDER BY prompt_version, tone;
  SELECT count(*) FROM findings WHERE tone IS NULL;
  ```

- Проверка успешна, если у новых находок с `prompt_version = 'v2'` появляются оценки `1..5`. Старые находки остаются без оценки; при некорректном ответе модели у новой записи может остаться `NULL`.
- Вручную открыть веб-ленту и получить сводку бота: оценка должна быть различима рядом с каждой находкой, у которой она есть.

## Задачи по порядку

Одна задача — один коммит с номером задачи в сообщении. Перед каждым коммитом запускать все тесты.

1. **Схема БД.** Добавить nullable-колонку `findings.tone` с ограничением `1..5` в `db/schema.sql`. Тест: `tests/test_schema.py` проверяет колонку, тип и ограничение.
2. **Оценка новых находок.** Обновить промпт и версию промпта в `worker/main.py`, добавить безопасный разбор `tone` и сохранение значения только для новых находок. Тест: `tests/test_tone.py` покрывает шкалу, некорректные ответы и сохранение оценки.
3. **Отображение в веб-ленте.** Добавить числовой цветной бейдж в `web/main.py`. Тест: `tests/test_web_badge.py` проверяет оценки `1..5`, прочерк для `NULL` и недопустимого значения.
4. **Отображение в сводке бота.** Добавить эмодзи в строку находки в `bot/main.py`. Тест: `tests/test_bot_lines.py` проверяет соответствие эмодзи оценке и отсутствие эмодзи для `NULL`.

## Открытые вопросы

Нет. По выбранному решению переанализируются только новые материалы; старые остаются без оценки.
